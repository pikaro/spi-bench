Media clean builds can fail on ESP32 DRAM when both the Bluedroid/ESP32-A2DP stack and the I2S/FFT media path are linked. In May 2026, `pio run -e media -j 1` after cleaning `.pio/build/media` failed at link with `.dram0.bss` overflow (~15.9 KiB). The SPI/PubSub clock-sync cleanup only adds a tiny helper object and is not the source of that BSS pressure. Treat media RAM/link failures as an audio/BT configuration issue unless the SPI/PubSub diff materially changes static storage.
