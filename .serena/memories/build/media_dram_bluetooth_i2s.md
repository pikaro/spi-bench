Media DRAM overflow root cause in May 2026 was the media app's aggregate `AudioSource` owning all backends at once (`I2SSource`, `WavSource`, Bluedroid `A2DPSource`, and `BtstackA2DPSource`) plus plain `env:media` linking Bluetooth deps while the active source was I2S. Fix direction: instantiate exactly one concrete source in `src/media/config.hpp` via `mediaAudioSourceKind`/`MediaAudioSourceBinding`, pass it directly to `FftAnalyzer`, keep inactive source configs as `inline constexpr` values only, and keep SDK/library deps aligned with the selected source. `env:media` is now I2S/WAV with `CONFIG_BT_ENABLED=n`. Avoid source-selection macros/ifdefs in `include/Audio`; Bluetooth source headers include their own stack deps and should only be included when that source is selected. Verified `bin/build -e media` succeeds at RAM 138,776/327,680 and flash 948,879/2,097,152, with no linked ESP32-A2DP/BTstack objects in the media map. On the connected media node, filtered logs showed I2S starting on BCLK GPIO25, WS GPIO32, DATA GPIO33 at 32 kHz mono 32-bit Philips and then `I2S source is producing data after 2 probe(s)`.
