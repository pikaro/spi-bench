# Media FFT workload isolation

On 2026-05-03 the media node FFT workload was moved off the SPI-facing core after full-bus tests showed media-originated traffic was source-limited by audio/display work. Active media config uses a SPH0645-compatible custom I2S link at 32 kHz, 1024-sample FFT/stride, 512-byte copy buffer, `AudioFft` priority 2 pinned to core 1, `FftDisplay` and `BeatLed` priority 1 pinned to core 1, and the media SPI slave task pinned to core 0. This preserves ~32 ms FFT frame cadence and ~31.25 Hz bin width while roughly halving I2S byte rate/FFT length vs 64 kHz/2048. After flashing, `/monitor` showed core 0 about 6% and core 1 about 34-40% with SPI disabled; `AudioFft` about 31-37% on core 1. `/metrics` showed beats flowing again (`audFft beat=20`, `audDisp beat=20` at ~72 s) and `/bpm` reported bass primary around 91.5 BPM in that capture. I2S ready recovery logging is rate-limited to avoid log spam if the source flaps.
