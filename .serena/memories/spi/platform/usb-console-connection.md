ESP-IDF USB Serial/JTAG exposes `usb_serial_jtag_is_connected()`, which reports host attachment via SOF packets. It does not mean a terminal program has opened the serial port. The project console abstraction now has `platform::Console::connected()`: hardware UART consoles return true because there is no reliable connection signal; USB Serial/JTAG console builds return the ESP-IDF host-attachment status. The console logging sink uses this to skip its formatting/write path while no USB host is attached.

ESP32-C3 upload note: esptool can transiently fail with `Failed to connect to ESP32-C3: No serial data received` even when the selected USB Serial/JTAG port and Python/PlatformIO environment are correct. Before treating this as an environment or port-selection problem, run the environment reset or erase target, then retry the upload.
