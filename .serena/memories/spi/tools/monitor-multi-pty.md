# monitor-multi PTY and package layout

PlatformIO's `pio device monitor` uses pyserial miniterm and calls `termios.tcgetattr()` on stdin during startup. Non-interactive Bash background jobs can give it `/dev/null`, which causes `termios.error: (19, 'Operation not supported by device')` before serial monitoring starts. Keep owned monitors running under a real pseudo-terminal.

`bin/monitor-multi` is now a thin Python entry point; the implementation lives under `bin/lib/monitor/` (`cli.py`, `ports.py`, `pre_ops.py`, `processes.py`, `output.py`, `runtime.py`, `state.py`). `bin/monitor` delegates to `bin/monitor-multi` and preserves `bin/monitor <env> [baud]` by converting the positional baud to `--baud`.

Current behavior: owned device ports are resolved in parallel via `bin/select_port.py`; optional `--upload`, `--uploadfs`, and `--reset` pre-ops run as stages before monitors start; monitor children are spawned via `pty.fork()`. The first instance for an env owns the serial monitor and writes a per-env spool under `/tmp`; later instances attach to the spool so each process gets the full stream. Do not replace this with a single output FIFO, because multiple FIFO readers split bytes instead of each receiving all bytes.

Operational caveat: do not rely on `bin/monitor-multi --upload` with multiple environments for validation. ESP32-C3/S3 USB/reset race conditions can make the combined upload pre-op fail even when separate uploads, or already-built same-chip reuploads, happen to work. Prefer uploading one environment at a time, then attach `bin/monitor-multi` without `--upload` for observation and routed commands.

Single-env mode is intentionally different from multi-env mode: output/log/filter text is unprefixed, and interactive stdin is forwarded directly to the owned PTY. Direct stdin mode must not use full `tty.setraw()` on the user's terminal: stdin/stdout are usually the same TTY, and raw mode disables terminal output processing such as newline-to-carriage-return mapping, causing monitor output to drift right. Use input-only cbreak-style termios changes instead: disable `ICANON` and `ECHO`, set `VMIN=1`/`VTIME=0`, and preserve output flags. If the process is only attached as a follower, bare input lines are forwarded through the per-env command FIFO. Multi-env mode keeps prefixed output and requires `!<env> <command>` for command routing.

Filtering supports repeated `--include` and `--exclude`, plus `--before`, `--after`, and `--context` for surrounding lines. Context is applied around lines that pass include/exclude matching; excluded lines are not emitted as context. `--timeout`, `--strip-ansi`, `--summary`, `--max-lines`, and `--log-file` remain supported.
